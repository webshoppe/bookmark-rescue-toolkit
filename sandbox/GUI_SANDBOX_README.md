# BRT GUI Sandbox

> **Optional contributor tool**
>
> This sandbox is for maintainers and contributors who need consistent screenshots or demo data.  
> It is **not required** to use Bookmark Rescue Toolkit.

A self-contained Windows Sandbox environment pre-loaded with the Bookmark Rescue Toolkit portable app and realistic mock browser data, using the exact folder structure from the documentation so field paths look authentic in screenshots.

> **Optional helper tools**  
> Firefox, Notepad++, ShareX, SumatraPDF, PeaZip and 7‑Zip are available via the host-backed    
> `C:\Bookmark_Rescue\tools\ → Desktop\SandboxTools\` mapping.  
> See `sandbox/tools/TOOLS_README.md` in the repo for setup details.

For an overview of both sandbox environments and shared setup, see [SANDBOX_README.md](SANDBOX_README.md).

## Quick Start (One-Click)

1. Put the latest portable app in `C:\Bookmark-Rescue-Toolkit`:

   - **Option A - Build from source:**  
     Build the portable app with `python build.py --zip`, then copy  
     `dist\Bookmark-Rescue-Toolkit\` to `C:\Bookmark-Rescue-Toolkit\`.

   - **Option B - Download from GitHub Releases:**  
     Download the latest `BookmarkRescue_vX.Y.Z.zip` from the repository's [**Releases page**](https://github.com/webshoppe/Bookmark-Rescue-Toolkit/releases), extract it, and place the extracted `Bookmark-Rescue-Toolkit\` folder at `C:\Bookmark-Rescue-Toolkit\`.

2. Copy *(do **not** Move)* the `tools/` folder from the repo (`sandbox/tools/`) to:
   ```text
   C:\Bookmark_Rescue\tools\
   ```
   Then download and place the portable apps inside it (see sandbox/tools/TOOLS_README.md).  
   Skip this step if you only need the GUI sandbox without the tools.

3. Double-click `Launch_GUI_Sandbox.bat`  
   (in `C:\Bookmark_Rescue\sandbox\` on the host).

4. Wait ~30-60 seconds for Windows Sandbox to load.

5. Inside the sandbox, Bookmark Rescue Toolkit will launch automatically with the recommended workspace already prepared.

Use these paths inside the Sandbox (they match the documentation exactly):

| Tab / Field                  | Path inside Sandbox                          |
|-----------------------------|----------------------------------------------|
| Tab 1 - Windows.old Path    | `C:\Windows.old`                              |
| Tab 1 - Output Directory    | `C:\Bookmark_Rescue\1_Raw_Extracted_Data`    |
| Tab 4 - Site Output Folder  | `C:\Bookmark_Rescue\2_Vault_Site`            |
| Tab 5 - Save Merged File As | `C:\Bookmark_Rescue\3_Merged`                |

## Two Separate Root Folders

The setup uses two distinct root folders that should not be confused.

> **Important distinction**:  
> `C:\Bookmark-Rescue-Toolkit\` (hyphen) = the app itself  
> `C:\Bookmark_Rescue\` (underscore) = the working workspace for screenshots

```text
C:\Bookmark-Rescue-Toolkit\          <- your repo (hyphen, matches GitHub name)
    dist\
        Bookmark-Rescue-Toolkit\
            BookmarkRescue.exe

C:\Bookmark_Rescue\                   <- screenshot workspace (underscore, matches docs)
    sandbox\                          <- all sandbox files live here
    Screenshots\                      <- shot output folder
	tools\                            <- copy from sandbox/tools/ (after cloning before running either sandbox)
    Windows.old\                      <- mock browser data (generated by launcher)
        Users\
            Alex\
            Jordan\
```

Inside the sandbox the workspace mirrors the docs exactly:

```text
C:\Windows.old\                       <- the mock source to scan (Tab 1 field)
    Users\
        Alex\      <- Chrome, Edge, Brave, Firefox
        Jordan\    <- Chrome, Brave, Firefox, Opera

C:\Bookmark_Rescue\                   <- workspace root
    1_Raw_Extracted_Data\             <- Tab 1 output
    2_Vault_Site\                     <- Tab 4 output
    3_Merged\                         <- Tab 5 output
```

## Prerequisites

> **tools folder location:**  
> The `tools/` folder lives at `sandbox/tools/` in the repo for organizational purposes but must be placed at `C:\Bookmark_Rescue\tools\` on your host - **not** inside `sandbox\`. Copy it there after cloning before running the sandbox. *(do **not** Move)* 

**Windows Sandbox** - enable via `OptionalFeatures.exe`, tick "Windows Sandbox", restart.

**Portable app built**:
```bash
cd C:\Bookmark-Rescue-Toolkit
.venv\Scripts\activate
python build.py --zip
```

Confirm `C:\Bookmark-Rescue-Toolkit\dist\Bookmark-Rescue-Toolkit\BookmarkRescue.exe` exists.

## Usage

### Step 1 - Run the launcher

Double-click:  
```text
C:\Bookmark_Rescue\sandbox\Launch_GUI_Sandbox.bat
```

> **Security warning on first run:**  
> Windows may show an "Unknown Publisher" warning when double-clicking the launcher. This happens because Windows tags files downloaded or extracted from a zip with a security zone marker.  
> To fix it permanently: right-click `Launch_GUI_Sandbox.bat` > Properties > tick **Unblock** at the bottom > OK. The warning will not appear again.

The launcher checks prerequisites, creates the Screenshots folder, generates `C:\Bookmark_Rescue\Windows.old\` if missing, prints the field paths to use, then opens the sandbox.

### Step 2 - Wait for the sandbox (30-60 seconds)

The startup script runs automatically and:
- Creates `C:\Bookmark_Rescue\` and all workspace subfolders
- Copies mock data to `C:\Windows.old\` inside the sandbox
- Creates desktop shortcuts to all workspace folders
- Sets Windows to dark theme
- Launches BookmarkRescue.exe
- Opens the Screenshots folder in Explorer

The launcher checks all prerequisites and prints their status:

```plaintext
 ============================================
  Bookmark Rescue Toolkit - Sandbox Launcher
 ============================================

 [OK] Windows Sandbox available.
 [OK] Portable app found.
 [OK] Screenshots folder exists.
 [OK] Mock data exists. Delete C:\Bookmark_Rescue\Windows.old to regenerate.

 -- Paths to use inside the sandbox -----------------------------

  Tab 1  Windows.old Path:    C:\Windows.old
  Tab 1  Output Directory:    C:\Bookmark_Rescue\1_Raw_Extracted_Data
  Tab 4  Site Output Folder:  C:\Bookmark_Rescue\2_Vault_Site
  Tab 5  Merger Output:       C:\Bookmark_Rescue\3_Merged\Merged_Bookmarks.html
  Search Search in:           C:\Bookmark_Rescue\1_Raw_Extracted_Data

  Screenshots: save to Desktop\Screenshots (syncs to host live)
  Use Snipping Tool directly - Win+Shift+S does not save in Sandbox.
 -----------------------------------------------------------------

 Launching sandbox...

Press any key to continue . . .
```

### Step 3 - Use these paths in the sandbox app

| Tab / Field | Enter this path |
|---|---|
| Tab 1 - Windows.old Path | `C:\Windows.old` |
| Tab 1 - Output Directory | `C:\Bookmark_Rescue\1_Raw_Extracted_Data` |
| Tab 4 - Site Output Folder | `C:\Bookmark_Rescue\2_Vault_Site` |
| Tab 5 - Save Merged File As | `C:\Bookmark_Rescue\3_Merged\Merged_Bookmarks.html` |
| Search - Search in | `C:\Bookmark_Rescue\1_Raw_Extracted_Data` |

Run in sequence before taking shots so all status labels show completed states:

1. Tab 1 - fill paths, Run Extraction, wait for green
2. Tab 4 - fill paths, Generate Vault Site, wait for green
3. Tab 5 - click "+ Add from Raw Folder", select `1_Raw_Extracted_Data`, set output, Merge Bookmarks
4. Search - click Search in header, set path, run a query (try: `github`)
5. View Docs - click the header button

**Tip:** Maximize the app window (`Win + Up Arrow`) before taking screenshots for the cleanest results.

### Step 4 - Take screenshots

Open **Snipping Tool** directly (search it in the Start menu).

> Note: `Win+Shift+S` copies to clipboard only inside Windows Sandbox and does not prompt to save. Use Snipping Tool > File > Save As instead.

Save to `C:\Users\WDAGUtilityAccount\Desktop\Screenshots\`

Files appear immediately in `C:\Bookmark_Rescue\Screenshots\` on your host.

## Regenerating Mock Data

To reset and regenerate:
```text
rmdir /s /q C:\Bookmark_Rescue\Windows.old
```

Then re-run `Launch_GUI_Sandbox.bat`.

## Adding to the Repo

Recommended placement as an optional supplemental folder:

```text
Bookmark-Rescue-Toolkit\
    sandbox\                          <- not included in dist build
        generate_mock_data.py
        GUI_Sandbox.wsb
        GUI_SANDBOX_README.md
        Launch_GUI_Sandbox.bat
        sandbox_startup.bat
```

The `sandbox\` folder is excluded from `build.py` automatically since it is not listed in `ASSETS_TO_COPY`. Add to the repo's `.gitignore` if desired:

```gitignore
# Sandbox generated data
sandbox/Windows.old/
```

## Troubleshooting

**Sandbox says "admin required" when creating folders**:  
This is expected behavior. The launcher script handles folder creation automatically.

**App doesn't launch**:  
Check that `BookmarkRescue.exe` exists in `C:\Bookmark-Rescue-Toolkit\dist\Bookmark-Rescue-Toolkit\`

**No screenshots appear on host**:  
Make sure you saved them to `C:\Users\WDAGUtilityAccount\Desktop\Screenshots\` inside the Sandbox.
